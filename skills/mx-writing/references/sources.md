## 2026-11-15 的升级：范围收到技术类文章

这一轮把适用范围明确为技术类文章，新增 `design-doc.md` 和 `research.md`，并按下面的材料调整了已有规则。两份文档在仓库的 `docs/designs/` 下；语料在 `docs/references/` 下，受版权保护，只作私人参考，不纳入版本管理，也不随 skill 分发。

| 材料 | 怎么用的 | 取了什么 |
|---|---|---|
| X 上的技术长文语料（1082 篇入选；统计时加上未入选的低互动 X 长文，共 1351 篇） | 同作者内对比写法特征与收藏率、点赞率；分五组细读 68 篇（英文讲解与教程 10、英文决策与基准 10、X 上的实战文与内容账号 14、中文原创 20、谈写作的文章 14） | 见下面两张表 |

**统计结果。** 取正文不少于 1200 字符、曝光不少于 1000 的 X 长文，只看有 4 篇以上的作者（英文 639 篇 48 位，中文 712 篇 33 位），在作者内部去均值后算相关系数。标题带数字、问句、"如何"、夸张词，开头用第一人称，篇幅，感叹号，破折号，"不是……而是"句式，与收藏率、点赞率的相关系数绝对值几乎都小于 0.1。超过 0.1 的只有中文里的两项：带代码（0.14）和对读者说"你"的密度（0.17）与收藏率正相关。每种语言比了八十多组，按 p<0.01 也会有一两组假阳性，所以这两项只当线索。结论是语料不支持任何"传播技巧"类的规则。

**细读后新增或加强的规则。** 至少在两篇实质高的文章里见到才收：

| 规则 | 见于 | 落点 |
|---|---|---|
| 坑和失败写四样：触发条件、原因、处置、还剩什么 | Addy Osmani、corbtt、trq212、DIYgod、yihong0618 | `longform.md` 四，`knowledge-doc.md` |
| 收益旁边写代价和没变的项；每个决定当场写代价 | Karpathy、DHH、DIYgod、Tw93 | `longform.md` 四，`report.md`，`design-doc.md` |
| 数字标明来路（自测、对方报告、估算）和可比性 | dexhorthy、Matt Shumer 的复盘、Dan Luu 的更正 | 主文件事实纪律 5，`research.md` |
| 数字后面写它推出的决定；用最小的构造例子钉住问题 | Eugene Yan、Hamel Husain、Simon Willison | `longform.md` 四 |
| 指标衡量什么、不衡量什么；一次只改一项并做对照 | Karpathy、Sebastian Raschka、dexhorthy | `research.md` |
| 已发布内容的更正：带日期，保留原文，写明怎么发现的 | Simon Willison、Karpathy、Dan Luu | `longform.md` 十一，`knowledge-doc.md`，`design-doc.md` |
| 开头交代材料来路，披露利益关系和 AI 的分工 | Tw93、DIYgod、meng shao | `longform.md` 三，`report.md` |
| 并列的短条目用同一结构，差异只表示真实差异 | Shreya Shankar（引 Frazier、Nielsen 等研究，作者未自测） | `report.md`，`en.md` |

**被好文章推翻或收窄的旧规则：**

| 旧规则 | 反例 | 改成 |
|---|---|---|
| 不写预告下文的句子 | Hamel、Eugene Yan 开头列出具体步骤；Tw93、DIYgod 交代哪部分亲手做 | 只禁空泛的预告，具体路线图和材料来路的交代保留 |
| 结尾不复述 | trq212 的 Lessons Learned、Hamel 和 Addy 的动作清单 | 操作类文章可以停在带条件的动作清单上，不出现新论断 |
| 结尾不展望 | Karpathy 把 33 年的实测外推到未来，每条对得上一项实测 | 允许写明前提的外推 |
| 每一节不用同一结构 | Addy 的七层评审、Harrison Chase 的五个问题 | 对象本身并列同构时可以，每节要有独有材料 |
| 对比从弱到强逐个展示 | Raschka、dexhorthy 的基准文一开头给全部结果 | 限于体验类，另设"基准、对比评测"原型 |
| 背景不一次倒完 | Guillermo Rauch 先集中讲三个前提，后文全部用上 | 后面每节都用的前提可以先给 |
| 小标题写判断或问题 | DIYgod 的一级小标题用主题词方便跳读 | 按模块跳读的长复盘，一级可以用主题词 |
| 去掉"你"做主语 | DIYgod、泊舟用"如果你……"帮读者对号入座 | 只删替读者预设身份和反应的"你" |
| 长文从一件具体的事开始、主线是判断 | Mechanical Watch、ARCHITECTURE.md、A half-hour to learn Rust | 是观点文和经验文的默认；讲解和教程从读者的问题开始 |

**看过但没有采纳的：**

- 标题和开头的钩子写法（数字、问句、夸张词、"我测了 100 小时"式的资历）。统计上看不出作用，细读里它们集中在实质最低的文章上。
- 结尾索取收藏、转发、关注和导流。
- 每日写作习惯、受众增长、故事脊柱、Pixar 叙事法则、"不要用限定词"、"写给八年级学生"、"不超过两页"。来自写作课和广告文案，面向涨粉和叙事；后三条和技术写作需要的限定、术语、由素材定篇幅直接冲突。
- "禁用词发现一个加一个"。和先前的对照实验结论相反，仍然只把词当线索。
- 让模型概括作者风格后直接写入风格说明。保留原规则：模型可以提候选，作者确认后才写入。
- 找选题的办法（同一件事讲过三次就写下来）。属于选题，不属于成文。
- 优化设计里与 HN 数据集绑定的部分：按投稿 ID 归并事件、追溯评论的父节点、按热度分层取样的配额。它们属于数据工具，写作规程只描述需要拿到什么材料。
- 优化设计里的 24 加 4 个案例的评测方案。这一轮只做了小规模对照试写，没有按那个规模执行。
- 交互式图解。超出文字规程的范围。

## 各家打架的地方，这里怎么取

| 分歧 | 取法 | 理由 |
|---|---|---|
| 硬禁用词，还是只当线索 | 当线索，看动作和密度 | adewale/anti-slop-writing 做过对照：在原则之上再叠加禁用词规则，18 组配对评分的差值全部是 0。Wikipedia 的识别指南也提醒，逐条消除特征只会让文章更难认，不会让它更好 |
| 破折号 | 生成的文字默认不用，作者原稿里的不动 | 各家从全禁到限频都有，Wikipedia 已把它列为"历史性特征"。默认不用是为了给模型一个简单的做法，不是因为它能证明什么 |
| 改多大 | 默认最小改动；结构问题先提议；只有结构层的机器腔才回到主线重排 | 作者的成稿里有他调过的句子，整篇重写没法逐处核对 |
| 句长节奏给不给配额 | 不给 | 为制造长短变化而改，会造出新的整齐 |
| 个人声音从哪来 | 材料、取舍、判断；口头禅和句式由作者的风格说明提供 | 口头禅配额换一个作者就失效，也最容易演过头 |
| 金句和升华 | 默认不写；作者素材里有他自己的感悟就保留 | 同上，这是个人风格，不是通用规则 |
| 小标题写结论还是写主题词 | 汇报、提案、公众号写结论或问题；会被反复更新、按目录查的设计文档写主题词 | 前者读者扫一遍就走，后者读者按目录定位，章节内容还会变 |
| 开头直给还是场景 | 汇报直给；长文可以从场景写起，但判断要在开头部分出现 | 取 compound-writing 的"按体裁判断位置" |
| 打不打分 | 不打分 | 分数会变成目标，稿子被改到刚好过线 |
| 初稿时读不读禁忌清单 | 起草后再读 | 取 human-writing 的做法：起草时只想内容 |
| 规则该不断加还是不断删 | 通用规则只并不加；个人风格的积累放进作者的风格说明 | tw93 主张 skill 要少而薄，卡兹克主张创作类要不断加。两人说的是两层东西，分开放就不冲突 |
| 改写能不能去掉机器腔 | 句子遍只做一轮；读着仍不对就回到素材和主线 | Pangram 与马里兰大学的研究称人工编辑过的模型文本仍更像模型写的；多位作者实测反复润色越改越差 |

## 没有采纳的

- 按字数或篇幅规定吐槽、自嘲、口语词的最低数量。
- 用错别字、故意不通顺来伪装。
- 允许先编经历再请作者确认。
- 以"通过 AI 检测"为目标的任何做法。
